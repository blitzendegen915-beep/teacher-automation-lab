# 大学採用ページ 巡回ツールの使い方

大学職員の求人は、転職サイトに出ないまま大学の公式採用ページだけで告知されることが少なくありません。
このツールは、登録した大学の採用ページを毎日巡回し、**前回から変わった部分のうち求人に関係しそうな行だけ**を抜き出してメールで知らせます。

- コード: `gas/university_job_watcher.gs`
- 対策資料: `docs/university_staff/`

---

## 1. 準備（初回のみ・10分）

1. Googleスプレッドシートを新規作成する（名前は「大学求人監視」など）
2. メニューの **拡張機能 → Apps Script** を開く
3. 既定の `コード.gs` の中身を消し、`gas/university_job_watcher.gs` の内容をすべて貼り付ける
4. 保存する（プロジェクト名は任意）
5. スプレッドシートに戻り、**再読み込み**する
6. メニューに **「大学求人監視」** が出るので、**初期設定（シートを作成）** を実行する
   - 初回は権限の確認画面が出ます。内容を確認して許可してください
   - 「このアプリは確認されていません」と表示された場合は、**詳細 → （プロジェクト名）に移動** から続行します（自分で作成したスクリプトのため）

作成されるシートは3つです。

| シート | 役割 |
| --- | --- |
| 監視先 | 巡回する大学と採用ページURLを入力する |
| 検知結果 | 更新を検知した行が追記される |
| スナップショット | 差分比較用の本文が自動保存される（**手動で編集しない**） |

---

## 2. 監視先の登録

「監視先」シートに、1行1ページで入力します。

| 列 | 内容 |
| --- | --- |
| A: 大学名 | 表示用の名前。「◯◯大学（法人事務局）」のように区別できる名前にする |
| B: 採用ページURL | **採用情報の一覧ページ**を指定する |
| C: メモ | 「専任職員の告知が出る場所」などの補足 |
| D: 有効 | チェックを入れた行だけ巡回する |
| E: 最終確認日時 | 自動で記入される |
| F: 前回の状態 | 「変更なし」「更新あり（3件）」「エラー: HTTP 403」などが自動で記入される |

サンプル行は「有効」がオフになっています。実際のURLに置き換えるか、行ごと削除してください。

### URLの選び方

- 「採用情報」「教職員採用」「求人情報」の**一覧ページ**を指定する（個別求人ページはすぐ消えるため不向き）
- 大学と学校法人でページが分かれていることがある。**両方登録してよい**
- トップページは更新が多すぎて通知が増えるため避ける

---

## 3. 実行

- **今すぐチェックする**：手動で1回巡回します。まずこれで動作確認をしてください
- **毎日の自動チェックを設定**：毎日7時台に自動で巡回し、結果をメールで送ります
- **自動チェックを解除**：自動実行を止めます

初回実行時は比較対象がないため、すべて「初回登録」となり、通知は出ません。**2回目以降から差分を検知します。**

---

## 4. 届くメール

```
大学採用ページ 巡回結果（2026/08/06）

■ 更新を検知した大学: 2件

【◯◯大学】
https://example.ac.jp/recruit/
  ・2027年度 専任職員（教務課）の募集について
  ・応募書類の受付は2026年9月30日必着とします

※ 検知は自動判定です。応募要項・締切・雇用形態は必ず大学公式ページ本文で確認してください。
```

更新が無かった日も「更新なし」のメールが届きます。動いていることの確認になります。不要なら `sendDigestEmail_` の冒頭で `updates.length === 0` のときに `return` するよう変更してください。

---

## 5. 検知結果シートの使い方

更新を検知した行は「検知結果」シートに追記されます。E列の「確認状況」を手で更新して管理します。

- `未確認` → `確認済`（求人ではなかった）
- `未確認` → `応募検討`（`docs/university_staff/06_応募管理と1校15分リサーチ.md` の台帳に転記する）

---

## 6. 検知の調整

コード冒頭の定数で調整できます。

| 定数 | 役割 |
| --- | --- |
| `INCLUDE_KEYWORDS` | この語を含む行だけ通知する。既定は「職員」「事務」「採用」「募集」など |
| `EXCLUDE_KEYWORDS` | この語を含む行は除く。既定は「教授」「准教授」など教員公募向けの語 |
| `MAX_LINES_PER_SITE` | 1ページあたりの通知行数の上限（既定15） |

**通知が多すぎる場合**：`INCLUDE_KEYWORDS` を「職員」「募集」など2〜3語に絞る。
**通知が少なすぎる場合**：`EXCLUDE_KEYWORDS` を減らす。ただし教員公募が混ざります。

---

## 7. 注意点

- **自動検知は補助**です。締切・雇用形態・応募資格は必ず大学公式ページの本文で確認してください
- 大学によっては、自動アクセスを制限していて取得できません。その場合「前回の状態」列に `エラー: HTTP 403` などが記録されます。そのページは**手動で巡回するリストに移してください**
- ページ全体が動的に生成されるサイト（JavaScriptで求人一覧を描画する等）では、更新を検知できないことがあります
- 監視先が多いと実行時間の上限に達することがあります。**30件程度までを目安**にしてください
- 取得先に負荷をかけないよう、1ページごとに間隔を空けています。実行間隔を1日1回より短くしないでください
- スナップショットシートは差分比較用です。手動で編集すると誤検知の原因になります
