# 03 小論文・作文対策｜大学職員採用試験

大学職員の筆記では、800字前後・60分の小論文が高頻度で出る。
評価されるのは文才ではなく、**課題を構造で捉えているか／大学職員の立場で書けているか／具体策があるか**の3点。

---

## 1. 型（これ以外は使わない）

### 800字の配分

| 段落 | 字数 | 内容 |
| --- | --- | --- |
| ① 序論 | 100〜150 | 問いを自分の言葉で定義し、結論を先に置く |
| ② 現状分析 | 200〜250 | なぜその課題が生じているかを、構造として説明する |
| ③ 具体策 | 300〜350 | **職員の立場で実行できる**施策を2つ。1つは自分の経験に紐づける |
| ④ 結論 | 100 | ①を言い換えて締める。新しい話題を出さない |

### 冒頭の書き出し（これで固定）

> 【テーマ】について、私は【結論】が最も重要だと考える。以下、現状の課題を整理した上で、大学職員として取り組むべき方策を述べる。

### 減点される書き方

- 「〜と思う」「〜ではないだろうか」の多用 → **「〜と考える」「〜である」で断定**
- 評論家で終わる（「大学は変わるべきだ」で止まる）→ **自分が何をするかを必ず書く**
- 教員目線で書く（「生徒」と書いてしまう）→ **「学生」。ここは即座にバレる**
- 具体策が抽象的（「連携を強化する」だけ）→ **誰と何をどうするかまで**
- 一人称が「僕」「自分」→ **「私」**

## 2. 頻出テーマ12（出題可能性の高い順）

1. 18歳人口減少の中で、大学が選ばれるために職員は何をすべきか
2. 大学職員に求められる資質・能力とは何か
3. 大学のDX（デジタル化）推進について、職員の立場から論じよ
4. 生成AIの普及は大学教育にどのような影響を与えるか
5. 教職協働の実現に向けて職員が果たすべき役割
6. 学生満足度を高めるために大学ができること
7. グローバル化への対応（留学生受入れ・派遣留学）
8. 社会人の学び直し（リカレント教育）と大学の役割
9. 高大接続改革と入試のあり方
10. 大学の広報戦略について
11. 学生の主体的な学びをどう支援するか
12. 本学の課題と、あなたが貢献できること（大学名入りの応用問題）

## 3. 骨子サンプル（そのまま使える3本）

### 骨子① 「18歳人口減少の中で大学が選ばれるために」

- **結論**：入学者の確保を広報の問題として扱う限り解決しない。入学から卒業までの学修体験の質を高め、それを可視化して外部に示すことが本質である。
- **現状分析**：
  - 18歳人口は減少局面にあり、募集競争は激化している
  - しかし定員充足だけを目標にすると、ミスマッチによる中退が増え、結果として評判を損なう
  - 受験生と保護者が見ているのは、偏差値だけでなく「入学後に何が身につき、どこへ進めるか」である
- **具体策1（広報）**：卒業生の進路とその過程を、学部・学科単位で具体的に示す。抽象的な理念紹介ではなく、履修モデルと接続する形で提示する。高校訪問では、進路指導担当が知りたいのは「うちの生徒がどう伸びるか」であり、その粒度の情報を用意する。
  - ※自分の経験：高校の進路指導担当として、大学から届く資料のどれが役に立ち、どれが読まれないかを見てきた
- **具体策2（入学後）**：初年次の段階で学修状況を把握し、つまずいた学生を早期に把握する仕組みを整える。出席や成績のデータを部署をまたいで共有し、支援につなげる。
  - ※自分の経験：高校で成績・出欠の集計を自動化し、担当者の勘に頼らず対象者を抽出できるようにした
- **結論**：選ばれる大学とは、広報がうまい大学ではなく、入学した学生が伸びる大学である。職員はその実態づくりと可視化の両方を担う。

### 骨子② 「大学のDX推進について、職員の立場から」

- **結論**：DXの成否を分けるのは技術ではなく、現場の業務をどれだけ具体的に把握しているかである。職員こそが推進の主体になるべきだ。
- **現状分析**：
  - 多くの大学でシステムは導入済みだが、紙と併用され、二重入力が残っている
  - 原因は、システムが実際の業務手順を反映していないこと、および現場の抵抗
  - 抵抗の正体は怠慢ではなく、「移行期に自分の負担が増える」という正当な懸念である
- **具体策1**：導入前に、対象業務の手順を工程単位で書き出し、どの工程が消えるのかを数字で示す。「便利になる」ではなく「この確認作業がなくなる」と言えて初めて現場は動く。
  - ※自分の経験：校務の自動化では、ツールの完成度より、手順書とエラー表示を整えたことが定着の決め手だった
- **具体策2**：全学一斉導入を避け、小規模な業務で成功例を作り、横展開する。あわせて、扱ってよい情報の線引きを規程として先に定める（特に生成AI利用時の個人情報）。
- **結論**：DXとは、システムを入れることではなく、業務のやり方を変えることである。業務を最もよく知る職員が主導すべきである。

### 骨子③ 「大学職員に求められる資質」

- **結論**：正確に処理する力と、制度を運用に翻訳する力の両立である。
- **現状分析**：
  - 従来、職員には定型業務の確実な処理が求められてきた
  - 現在は、認証評価や内部質保証への対応、中期計画の実行など、企画・分析の役割が拡大している
  - SDの義務化も、職員を大学運営の担い手と位置づける流れの一部である
- **具体策1**：制度の趣旨を理解した上で、学生と教員それぞれに通じる言葉に翻訳して伝える。規程をそのまま示すだけでは運用は回らない。
- **具体策2**：業務を個人の記憶ではなく記録として残し、担当者が代わっても継続する状態をつくる。
- **結論**：職員に求められるのは、正確さという土台の上に、大学の将来構想を日々の運用へ落とし込む力である。

## 4. 書く前の3分（本番の手順）

1. 設問を読み、**問われているのは「原因」か「対策」か「意見」か**を確認（ここを外すと0点に近い）
2. 余白に結論を1行だけ書く
3. 具体策を2つ、キーワードだけ書き出す（うち1つは必ず自分の経験）
4. 段落配分の字数を余白にメモ
5. 書き始める。**書きながら結論を変えない**

## 5. 時間配分（60分・800字の場合）

- 構想 5分／執筆 45分／見直し 10分
- 見直しは **誤字・「生徒」→「学生」・文末の断定・字数** の4点だけ見る

## 6. 練習（本番前にやること）

- 上記テーマから**最低3本**を、手書き・時間を計って書く（PCで書くと本番の速度が読めない）
- 書いた3本を並べ、**使い回せる具体策の型**を2つに絞る
- 出題テーマが違っても、DX・高大接続・学修支援の3方向に寄せれば、自分の経験に接続できる
