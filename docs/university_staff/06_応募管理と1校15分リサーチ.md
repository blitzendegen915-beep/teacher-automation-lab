# 06 応募管理と「1校15分」リサーチ手順

数を出す段階では、1校あたりにかける時間を固定する。
**汎用ESは完成済み（`05_ES回答ストック.md`）。あとは ▼ を埋めるだけ**という状態を維持する。

---

## 1. 1校15分リサーチ（この順番・この時間で切る）

| 時間 | やること | 拾うもの |
| --- | --- | --- |
| 0〜3分 | 求人票を読む | 職種、想定配属、応募資格、必要書類、締切、選考フロー、勤務地 |
| 3〜7分 | 公式サイト「大学案内／建学の精神」 | **理念を一文で**。創立者・設立経緯に特徴があればメモ |
| 7〜11分 | 「中期計画／将来構想／グランドデザイン」 | **計画の名称**と**柱を1つ**。PDFは目次と柱だけ見る |
| 11〜14分 | 「ニュース／トピックス」直近3か月 | 新設学部、協定締結、DX関連、国際関連の**具体的な取組名を1つ** |
| 14〜15分 | 台帳に記入 | 下記の項目を埋める |

> **3分ルール**：中期計画が見つからない大学もある。3分探して無ければ諦め、ニュースからネタを2つ取る。完璧を狙って時間を溶かさない。

### 拾った情報の入れ先（`05` の ▼ に対応）

| 拾ったもの | 入れる場所 |
| --- | --- |
| 理念（一文） | 設問1「▼貴学の【理念】には〜」 |
| 中期計画名＋柱 | 設問1「【具体的な取組名】について」 |
| 直近の取組 | 設問1 または 面接の逆質問 |
| 想定配属・注力領域 | 設問3「▼貴学の【志望部署】において」 |

### 自分の経験との接続（3パターンで足りる）

拾ったネタが何であっても、以下のどれかに寄せれば自分の経験に接続できる。

| 大学側のキーワード | 寄せる自分の経験 |
| --- | --- |
| DX、業務改善、情報化、データ活用、AI | 校務の自動化・生成AIの業務実装 |
| 高大接続、附属校、入試改革、総合型選抜、高校連携 | 大学附属校での勤務・進路指導・高校現場の視点 |
| 国際化、留学、グローバル、英語教育 | 英検1級・英語史の学術的訓練・検定運営 |
| 学生支援、初年次教育、キャリア、学修支援 | 担任・進路指導・面談の実務 |
| 地域連携、広報、ブランディング | 学校説明会・私学展・Webサイト運営とSEO |

## 2. 応募管理台帳（項目）

`data/` などにスプレッドシートを1枚作り、以下を管理する。
教員採用で運用している出願締切一覧と**同じ運用**にすれば、朝の確認を一本化できる。

| 列 | 内容 | 備考 |
| --- | --- | --- |
| 大学名 | 正式名称 | 法人名も併記 |
| 求人経路 | マイナビ／大学公式／その他 | 経路で応募方法が変わる |
| 職種 | 総合職／教務／入試広報 等 | |
| 雇用形態 | 専任／契約／嘱託 | **専任かどうかは最優先の確認項目** |
| 締切 | 日付 | 必着／消印有効を必ず併記 |
| 必要書類 | 履歴書・職務経歴書・ES・証明書 | **証明書は発行日数があるので別管理** |
| 選考フロー | 書類→筆記→一次→最終 等 | 筆記の形式（SPI／小論文）も |
| 理念メモ | 一文 | ESの▼に直接使う |
| 中期計画メモ | 名称＋柱 | 同上 |
| ステータス | 未着手／作成中／提出済／結果待ち／通過／不合格 | |
| 次アクション | 具体的な動詞で | 「◯◯を印刷」「証明書を申請」 |
| 期限 | 次アクションの期限 | 締切ではなく**自分の作業期限** |

### 運用ルール

- **締切の3日前を自分の締切**として台帳に入れる（郵送・証明書の遅延吸収）
- ステータスが「作成中」のまま5日動いていない案件は、**出すか捨てるかを決める**
- 同時進行は**5校まで**。それ以上は質が落ちて全滅する
- 教員採用の台帳と**同じシートに混ぜない**。志望動機の書き分けが崩れる

## 3. 事前準備（応募のたびに発生させない）

一度やれば全応募で使い回せるもの。**今週中に終わらせる**。

- [ ] 卒業証明書・成績証明書・修了証明書を**複数部まとめて取得**（発行に日数がかかる。応募のたびに申請すると間に合わない）
- [ ] 英検1級の合格証明書の所在確認（紛失していれば再発行手続き）
- [ ] 教員免許状のコピーをPDF化（イー・スタッフ提出用に作ったデータが流用できる）
- [ ] 証明写真をデータで確保（3か月以内・スーツ・背景無地）
- [ ] 職務経歴書（大学職員版）を確定させ、**PDFとWordの両方**で保管
- [ ] 汎用ES（`05`）を、200字版・400字版でそれぞれ確定
- [ ] 履歴書の定型部分（学歴・資格）をデータ化

## 4. 週次の回し方

| 曜日 | やること |
| --- | --- |
| 平日朝（10分） | マイナビ／大学公式の新着を確認、台帳に追加 |
| 平日夜（30分） | 1校リサーチ＋ESの▼埋め＝1校分を仕上げる |
| 週末（2時間） | 提出作業（印刷・郵送・Webフォーム）、小論文を1本書く |

**1日1校**を維持すれば、月20校に応募できる。大学職員の中途は倍率が高く、母数を確保することが最も効く。

## 5. 提出前の最終確認（毎回・3分）

- [ ] `▼` `【　】` が残っていないか（検索して確認）
- [ ] 大学名が正式名称か、**他大学の名前が混入していないか**（使い回し最大の事故）
- [ ] 「生徒」が志望動機・自己PRに紛れていないか
- [ ] 指定字数の9割以上あるか
- [ ] 必要書類が全部揃っているか
- [ ] 締切と提出方法（必着／消印有効／Web）が合っているか
