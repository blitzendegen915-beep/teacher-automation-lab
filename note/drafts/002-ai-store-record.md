# プログラミング未経験の高校教員が、AIに全部書かせて販売サイトを公開するまで

自分で作った教材を売ってみようと思ったとき、最初に調べたのは「どこで売るか」でした。

プラットフォームはたくさんあります。ただ、どれも手数料が10〜30%かかります。300円の教材を売って、手元に残るのが200円ちょっと。それ自体が悪いとは思いませんが、**「じゃあ自分のサイトで売ったらどうなるんだろう」**という疑問が消えませんでした。

問題は、私がプログラミングを本業でやったことがないことです。★（← 経験の有無を正確に。「Excelの関数までは書ける」「GASを少し触ったことがある」など、実際のレベルを1行で）

結論から言うと、**サイトはできました**。公開もしています。

https://blitzendegen915-beep.github.io/edusup

サーバー代は月0円。決済手数料以外の中間手数料もゼロ。商品を追加するときは、テキストファイルを1行足すだけです。

そして、そのコードのほぼ全部を、私は自分で書いていません。AIに書かせました。

この記事は、その全記録です。

## できたもののスペック

先に、何ができたのかを正確に書いておきます。

- **商品一覧ページ**と、**商品ごとの個別ページ**（検索から直接入ってこられる）
- 「ご購入の流れ」「よくある質問」「運営者について」「特定商取引法に基づく表記」の固定ページ
- Google検索向けの構造化データと `sitemap.xml`（検索に載るための最低限）
- クレジットカード・PayPay・コンビニ決済（Stripe の支払いリンクを使用）
- 無料商品はその場でダウンロード、有料商品は決済後にダウンロード
- スマートフォン対応

かかったお金は、**ドメイン代も含めて0円**です。★（← 独自ドメインを取ったなら、その金額に書き換え）
かかった時間は、★（← 実際の日数・時間。「土日2日」「平日夜に少しずつ2週間」など）

## 使ったもの

3つだけです。

**1. GitHub Pages（無料）**
GitHub というサービスに置いたファイルを、そのままWebサイトとして公開してくれる機能です。無料で、広告も入りません。サーバーの契約もレンタルサーバーの管理画面も出てきません。

**2. Stripe（決済のみ手数料）**
決済サービスです。「支払いリンク」という機能があり、**商品ごとにURLを1本発行するだけ**で決済ページが用意できます。カード番号などは全部Stripe側で処理されるので、こちらのサイトが個人情報を持ちません。ここが精神的にいちばん大きかったです。

**3. AI（コードを書く役）**
今回のいちばんの主役です。私がやったのは「こういうものが欲しい」と日本語で伝えることと、出てきたものを見て「ここが違う」と言うことだけです。

## 「AIに作らせる」の実際

ここが一番誤解されている気がするので、正直に書きます。

**「サイト作って」で作れるものは、使い物になりません。**

最初にやったのはまさにそれで、それらしいものは出てきました。見た目はきれいです。でも、商品を1個増やすたびにHTMLを手で書き足す構造になっていて、これでは続きません。

うまくいき始めたのは、**「何を作るか」ではなく「どう運用したいか」を伝えるようにしてから**でした。

たとえば、こう言い換えました。

> ❌「教材を売るサイトを作って」
> ⭕「商品情報を1つのファイルにまとめて書いておくと、そこからページが自動生成される仕組みにしてほしい。商品を増やすときに触るのはそのファイルだけにしたい」

出てきたものが変わりました。前者は「ページ」を作りますが、後者は**仕組み**を作ります。

実際いまのサイトは、`products.json` というファイルに商品を追記して保存すると、それだけでページが増えて、検索用の `sitemap.xml` まで更新されます。私が触るのはそのファイル1つです。

もう一つ効いたのが、**AIへの常設の指示書を用意したこと**です。「初心者がそのまま使えるように手順を必ず書く」「個人情報は絶対にダミーデータで実装する」といった方針をファイルにまとめて置いておくと、毎回言わなくても守られるようになりました。これは想像以上に効きました。

### 全体の流れ

1. GitHub のアカウントを作る
2. リポジトリ（ファイル置き場）を1つ作る
3. AIに、商品ファイルからページを生成する仕組みを作らせる
4. GitHub Pages を有効にして公開する
5. Stripe で支払いリンクを作り、商品に紐づける
6. 法定表記（特定商取引法）を整える

順に書きます。

### 1. GitHub のアカウントとリポジトリ

GitHub は無料です。アカウントを作ったら、リポジトリを1つ作ります。名前はサイトのURLに入るので、短く分かりやすいものにします。

**公開（Public）にしてください。** GitHub Pages を無料で使う条件です。「コードが全部見えてしまうのでは」と不安になりますが、見えるのはサイトを作るためのファイルです。**販売する商品ファイル自体をここに置いてはいけません**（後述）。

### 2. AIへの指示書を先に置く

これを最初にやるかどうかで、後の作業量が変わります。

リポジトリの一番上に `AGENTS.md` というファイルを作り、AIに毎回守ってほしい方針を書いておきます。私が書いているのは、たとえばこういう内容です。

```markdown
# AGENTS.md

## 基本方針

- 出力するコードは、原則としてそのまま貼り付けて実用できる状態にする。
- 初心者でも使えるように、設置手順・実行手順・注意点を必ず書く。
- 既存ファイルを変更する場合は、変更理由を簡潔に説明する。
- 個人情報を扱う可能性がある場合は、必ずダミーデータで実装する。
- 既存UIがある場合は、見た目を壊さず機能追加する。

## 納品時に報告すること

1. 変更したファイル
2. 追加した機能
3. 使い方
4. テスト方法
5. 注意点
6. 次に改善できること
```

短いですが、これがあるとAIの出力が安定します。特に「**手順を必ず書く**」「**見た目を壊さず機能追加する**」の2つは、毎回言わずに済むだけで相当楽になります。

### 3. 実際に出した指示（プロンプト）

ここが一番知りたい部分だと思うので、実際に近い形で出します。

**最初の指示**

```
自作の教材（PDF・Excel）を販売する静的サイトを作ってください。

条件:
- 商品情報は products.json に1か所でまとめて書き、そこからページを生成する
- 商品を追加するときに触るファイルは products.json だけにしたい
- 生成するもの: トップの商品一覧、商品ごとの個別ページ、sitemap.xml
- Google検索で商品ページが直接ヒットしてほしいので、構造化データを入れる
- npm install なしで動かしたい。Node.js の標準機能だけで書く
- スマートフォンで見られること
```

最後の2行が地味に重要です。「npm install なし」を指定しないと、依存関係の管理が必要な構成が出てきて、初心者には維持できなくなります。**自分が維持できる範囲を先に宣言する**のがコツです。

**2回目以降の指示のしかた**

出てきたものを見て、こう返していきます。

```
商品ページに、購入前に中身が分かる画像を出したい。
products.json の images に複数のファイル名を書けるようにして、
画像がない商品でもレイアウトが崩れないようにしてください。
```

```
まだ販売を開始していないので、
「準備中」であることがサイト全体に表示されるモードがほしい。
site.json のフラグ1つで切り替えられるようにしてください。
```

ポイントは、**1回に1つのことだけ頼む**ことです。「あれもこれも」と言うと、どこが壊れたのか分からなくなります。

### 4. 商品ファイルの構造

`products.json` は、商品を配列で並べるだけです。1商品はこうなります。

```json
{
  "id": "grammar-worksheet-subjunctive",
  "title": "英文法ワークシート「仮定法」（PDF・全8ページ）",
  "category": "ワークシート",
  "audience": ["高校生", "教員"],
  "price": 300,
  "fileType": "PDF",
  "summary": "仮定法過去・仮定法過去完了を段階的に練習できるワークシート。",
  "details": [
    "基本問題20問＋応用問題10問",
    "解答・板書用解説つき（別ページ）",
    "B5印刷を想定したレイアウト"
  ],
  "tags": ["高校英語", "文法", "仮定法"],
  "paymentLink": "",
  "downloadFile": "",
  "updated": "2026-07-03",
  "images": ["grammar-worksheet-subjunctive.png"]
}
```

`id` がそのまま商品ページのURLになります。**半角英小文字・数字・ハイフンだけ**にしてください（日本語を入れるとURLが壊れます）。

`paymentLink` に Stripe のURLを入れると「購入する」ボタンが有効になります。`price` を `0` にすると無料配布になります。

**無料サンプルを1つ置くことを強くおすすめします。** 誰も知らない個人のサイトで、いきなり300円を払う人はほとんどいません。無料で品質を確かめてもらう入口が要ります。

### 5. GitHub Pages で公開する

リポジトリの「Settings」→「Pages」で、公開元を設定します。

私は GitHub Actions でビルドして公開する形にしています。`.github/workflows/` に設定ファイルを1つ置くと、**`products.json` を書き換えて保存するだけで、数分後にサイトが更新される**状態になります。手元でコマンドを打つ必要はありません。

ここもAIに頼めば書いてくれます。指示はこうでした。

```
main ブランチに push されたら、
web/shop/build.js を実行して、生成された dist/ を
GitHub Pages に公開するワークフローを作ってください。
```

**注意点が1つあります。** 初回は Pages の設定が反映されるまでに数分〜十数分かかることがあり、その間はページが見つからない状態になります。慌てて設定を触り直すと余計に混乱するので、いったん待ってください。★（← 実際に待った時間があれば、それを書くと親切）

### 6. Stripe の支払いリンク

Stripe のアカウントを作り、ダッシュボードで「支払いリンク」を作ります。

1. 商品名と価格を入れる
2. 支払い方法（カード・コンビニ決済など）を選ぶ
3. 生成されたURLをコピーする
4. `products.json` の `paymentLink` に貼る

これだけです。決済ページはStripe側にあるので、こちらのサイトはカード情報に一切触れません。

**決済後のファイル配布**については、Stripe の「支払い後のリダイレクト先」と、決済完了メールの2経路を使っています。

そして最重要の注意点です。

> **販売するファイル本体を、公開リポジトリに置かないでください。**

公開リポジトリに置いたファイルは、URLさえ分かれば誰でも取得できます。決済を通さずにダウンロードできてしまいます。有料商品の実体は、別の場所（Stripe の商品ファイル配信機能や、限定公開のストレージ）に置いてください。無料配布のファイルだけがリポジトリに置けます。

### 7. 特定商取引法の表記

個人でデジタル商品を売る場合でも、表記は必要です。私は次の項目を1ページにまとめています。

- 販売者名
- 運営責任者
- 所在地
- 連絡先
- 販売価格
- 商品代金以外の必要料金
- 支払方法・支払時期
- 引渡し時期
- 返品・キャンセルについて

住所・電話番号については、**「請求があったら遅滞なく開示する」という運用が認められる場合があります**が、条件があります。自分がどれに当たるかは、消費者庁の案内を必ず自分で確認してください。ここは他人の記事を信じて済ませていい部分ではありません。私も最終的には自分で読みました。★

デジタル商品は原則として返品を受け付けない旨を明記しますが、**ファイルが開けない・破損しているといった不具合には対応する**と書いておくほうが、結果的にトラブルが減ります。

### 8. 公開したあとにやること

- `sitemap.xml` を Google Search Console に登録する
- 商品ページのタイトルに、検索されそうな言葉を入れる（「高校英語 仮定法 プリント」など）
- 無料商品を入口にして、そこから有料商品に導線を張る
- note の記事から自分のサイトへ、サイトから note へ、相互にリンクする

最後のものが、この記事を書いている理由でもあります。
