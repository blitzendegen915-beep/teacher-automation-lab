# Excelの `=COPILOT()` が1年で消える。AIはセルの中に座れなかった

窓の杜を見ていたら、Excelの `=COPILOT()` 関数が廃止されると出ていた。2026年9月14日以降、新しい数式では使えなくなる。

登場したのが2025年8月なので、1年で終わることになる。しかも正式版として一般提供されるところまで行かず、Microsoft 365 Insider と Frontier のプレビュー段階で姿を消す。

1年。

生成AIの世界ではモデルが何世代か進む長さだから、驚くほどの話ではないのかもしれない。ただ、この関数の仕組みをあらためて眺めていると、Excelと生成AIという二つの道具の性格の違いが、やけにはっきり見えてくる。

Microsoftは失敗だったとは言っていない。廃止の理由として説明されているのは、Excel内のCopilot体験を整理するため、というものだ。

## セルの中にChatGPTが入った

COPILOT関数が何だったのかを先に書いておく。仕組みそのものは面白い。

普通のExcelなら `=SUM(A1:A10)` と書けばA1からA10を合計する。COPILOT関数では、ここに日本語を書けた。

Microsoftが示していた基本形はこうだ。

```
=COPILOT(prompt, context)
```

自由記述のアンケートが大量に並んでいるとする。そこで、

```
=COPILOT("次の意見を肯定・中立・否定に分類してください",B2)
```

と書く。B2の文章をAIが読んで分類し、結果をセルに返す。

2025年の発表時、Microsoftは分類・要約・文章生成といった用途を挙げていた。しかもこの機能はExcelの計算エンジンに組み込まれていて、参照先のデータが変わればAIの出力も再計算される。

初めて見たときは未来を感じた。ChatGPTを開いて、Excelからデータをコピーして、プロンプトを書いて、返ってきた答えをまたExcelに戻す。あの往復がいらなくなる。Excelを使う人間からすれば夢のような話だ。

ただ、よく考えると変なのだ。

## Excel関数は「同じ答えが出る」から使える

Excelには独特の安心感がある。

`=1+1` は今日やっても2で、明日開いても2だ。Microsoftが大型アップデートをしたからといって、突然3にはならない。

当たり前すぎる話だが、仕事でExcelが使えるのはこの当たり前が守られているからでもある。SUMもAVERAGEもIFも、入力と計算方法が同じなら結果も同じになる。だから給与計算に使える。成績処理にも、売上集計にも使える。

生成AIは、もともとそういう道具ではない。

同じ指示で同じ文章が返るとは限らない。モデルが更新されれば出力も変わる。Microsoft自身も、COPILOT関数はAIが生成した回答なので正確性を確認するように案内していた。

ここで奇妙なことが起きる。

`=SUM(A1:A10)` と `=COPILOT(...)` は、見た目としては同じExcel関数だ。しかし前者は計算で、後者は判断である。同じ `=` から始まっているせいで、同じ種類のものに見えてしまう。

電卓と相談相手を、同じ引き出しに入れたようなものだ。

## 「使いすぎです」と言ってくる関数

COPILOT関数には、普通の関数にはない特徴がもう一つあった。回数制限がある。

窓の杜によれば、10分間に100回までという上限があり、超えると `#CONNECT` エラーになる。Copilotのライセンスとインターネット接続も要る。

仕組みを考えれば当然ではある。COPILOT関数はPCの中で足し算をしているわけではなく、AIモデルに処理を投げて回答を作らせている。普通の関数より重い。

それでもExcelの感覚で考えると、なかなか不思議だ。

SUM関数を101回使ったところで「本日のSUMは使いすぎです」とは怒られない。IF関数は疲れない。VLOOKUPは、古参社員のような顔をしながら黙々と働く。

AIになるとそうはいかない。クラウドの計算資源を使う以上、利用制限も通信もライセンスも絡んでくる。シートの中にAIを持ち込むと、それまで見えなかったAI側の事情まで一緒に入ってくる。

関数として扱うには、癖が強かった。

## では、MicrosoftはExcelのAIを諦めたのか

ここは誤解されやすいところだ。

Copilot in Excel そのものが終わるわけではない。むしろ逆で、Excel全体をCopilotから操作させる方向に進んでいる。

いまのCopilot in Excelは、自然言語で頼むと、数式・表・グラフ・ピボットテーブルといったExcel本来の機能を使ってブックを編集する。モードも Edit・Plan・Chat の3つに分かれた。Editは実際に編集し、Planは手順を考え、Chatはブックを変更せずに相談だけ受ける。

撤退ではない。AIを置く場所が変わった、という話だ。

以前は、AIそのものを関数にしようとしていた。いまは、AIにExcelを操作させようとしている。

この違いは大きい。

## 答えを出させるより、式を書かせる

ここからは私の見方になる。

生成AIとExcelは相性がいい。ただし、AIに計算結果そのものを出させる必要は、たぶんない。

「A列がクラス、B列が点数です。クラスごとの平均点を出してください」とCopilotに頼む。AIがExcelの構造を読んで `=AVERAGEIFS(...)` のような式を書く。計算はExcelがやる。

役割分担として自然だ。人間が「何をしたいか」を伝え、AIが「どう書けばいいか」を考え、Excelが「その通りに正確に実行する」。得意分野がきれいに分かれている。

しかも、AIが作った結果が通常の数式や表として残るので、あとから人間が直せる。ここが大きい。セルに答えだけが返ってくる形だと、その答えがどこから来たのか誰にも分からなくなる。半年後に自分で見ても分からない。

私はこの形のほうが好きだ。AIに全部やらせるのではなく、AIに道具を使わせる。生成AIが強くなるほど、こちらが重要になる気がしている。

## 2025年の「未来」が、2026年には消える

もう一つ面白いと思ったことがある。

Microsoftは2025年8月、COPILOT関数をかなり前向きに発表していた。自然言語とExcelの構造化されたロジックをつなぎ、これまでにないワークフローを生む機能として紹介している。その発想自体は、いま読んでも面白い。

それが約1年で廃止される。

生成AIの世界では、このくらいの速度で「未来の形」が書き換わる。

少し前まで、AIをアプリにどう入れるかが盛んに議論されていた。チャット欄を付ける。AIボタンを付ける。AI関数を追加する。いまはその発想自体が変わりつつある。機能としてアプリの隅に置くのではなく、アプリ全体を理解させて、複数の機能をまたいで操作させる方向へ動いている。

Excelだけを見ても、その変化が分かりやすい。

だから今回のニュースは「ExcelのAI機能が失敗して消えた」という話ではない。もう少し微妙で、もう少し面白い。

正確さと再現性を積み重ねてきたソフトウェアの中に、確率的に答えを作るAIをそのまま関数として入れてみた。やってみたら、座りが悪かった。だから今度はセルの外に出して、Excelそのものを操作させている。試行錯誤の途中なのだと思う。

`=COPILOT()` という名前は消える。その1年が無駄だったとは思わない。

生成AIは既存の道具のどこに座れば一番うまく働けるのか。その答えを探している途中の、興味深い失敗作だった。

こういう短命な機能のほうが、案外その時代の空気を残している。
