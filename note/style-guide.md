# AIが書いたと思われない日本語にする

ChatGPT等が出した原稿を note 用に直すための対応表です。
`note/tools/ai-check.js` で機械的に拾える部分と、人間が判断する部分に分けています。

---

## 大前提：AI臭は語彙ではなく「均一さ」から出る

読者が「AIっぽい」と感じる瞬間は、たいてい次の3つです。

1. **文の長さが揃っている** — 全部が40〜50字。人間はもっとバラつく
2. **段落が全部同じ型** — 「主張 → 理由 → まとめ」が毎回きれいに揃う
3. **固有名詞と数字がない** — 「ある企業では」「多くの場合」で済ませてしまう

単語を言い換えても、この3つが残っていると匂いは消えません。**逆にこの3つを直せば、多少カタい語彙が残っていても人間が書いたように読めます。**

直す順番もこの通りです。まず構造、次にリズム、最後に語彙。

---

## 1. 構造を壊す（最優先）

### 「まとめ」を消すか、まとめらしくないものにする

AIは必ず最後に要約を置きます。人間はそんなに親切ではありません。

> ❌ 「いかがでしたか。今回は◯◯について解説しました。ぜひ試してみてください。」
> ⭕ 「浮いた17分で問題の中身を考えられます。省略できるのは作業であって、中身ではありません。」

最後は**要約ではなく、言い切り・引っかかり・次への振り**で終わらせます。

### 見出しの形を揃えない

AIは見出しを同じ品詞で揃えます。わざと崩します。

> ❌ 「◯◯のメリット」「◯◯の手順」「◯◯の注意点」（全部が名詞句）
> ⭕ 「なぜ作ったか」「どう動くか」「つまずいたところ」「それで、売れたのか」

疑問形・体言止め・会話文を混ぜる。1つだけ極端に短い見出しを入れると効きます。

### 箇条書きを「3つ」で揃えない

AIは何でも3つか5つにします。**2つでも6つでもいい**し、そもそも箇条書きにせず地の文で書いたほうが人間らしい箇所も多いです。

箇条書きの各項目の長さも揃えない。1つだけ長く書く。

### 段落の長さをバラす

3行 → 1行 → 5行 → 1行、のように。**1行だけの段落**を意図的に混ぜると、それだけで機械っぽさが落ちます。

---

## 2. リズムを壊す

### 短い文を混ぜる

これが最も効きます。

> ❌ 「この作業には毎回20分程度かかっており、しかも同じ作業を毎週繰り返す必要があるため、年間で考えると相当な時間を費やしていることになります。」
>
> ⭕ 「この作業をやめました。」
> 　「毎回20分。しかも来週も再来週もやる。」

**10字以下の文**が1つも無い原稿は、ほぼAI原稿です。

### 文末を連続させない

「です。」「ます。」が3つ続いたら1つ崩します。

- 体言止め：「問題は**作る側**です。」→「問題は作る側。」
- 疑問：「〜ではないかと思います」→「〜なんでしょうか。」
- 中止法：「〜であり、」
- 「〜でした」「〜ました」で過去形を混ぜる

### 一文を60字で切る

60字を超えたら、たいてい2文に割れます。読点で繋いでいる箇所が切れ目です。

---

## 3. 語彙を直す（機械的に置換できる）

### 冗長表現

| AI原稿 | 直し |
| --- | --- |
| 〜することができます | 〜できます |
| 確認を行う / 対応を行う | 確認する / 対応する |
| 〜という点において | 〜は |
| 〜における | 〜の |
| 〜する上で | 〜するとき |
| 〜となっています | 〜です |
| 〜していきましょう | 〜します |
| 必要があります | 要ります / いります |
| 可能です | できます |

### 定型のAIフレーズ（原則すべて削除）

- いかがでしたか / いかがでしょうか
- ぜひ〜してみてください
- 〜と言えるでしょう / 〜と言えます
- 〜ではないでしょうか
- 近年 / 現代社会において / 昨今
- 〜が重要です / 〜が大切です（何がどう重要かを具体に書き換える）
- 効率的に / 効果的に / 最適化
- 〜を活用して（→「〜を使って」）
- 〜を実現します（→「〜できます」「〜になります」）
- 結論から言うと（1回だけなら可。2回出たらAI）
- ポイントは3つあります

### 翻訳調

日本語は主語を落とします。AIは英語の癖で主語を書きすぎます。

> ❌ 「あなたがこの方法を使えば、あなたの作業時間は短縮されます。」
> ⭕ 「この方法なら作業時間が減ります。」

- 「私たちは」「あなたは」はほぼ全部消せます
- 「〜されます」（受動態）→ 能動に
- 「劇的に」「飛躍的に」「革新的な」→ 誇張は消す

### 説明口調・指導口調

note の読者は生徒ではありません。

> ❌ 「まずは基本を理解しましょう。次に応用に進みます。」
> ⭕ 「先に仕組みだけ書きます。手順は後ろです。」

---

## 4. 具体性を足す（AIが最も苦手な部分）

ここが人間らしさの本体です。**削るより足すほうが効きます。**

### 数字を入れる

「かなり時間がかかる」→「20分」
「多くの人が」→ 書けないなら消す（嘘の数字は入れない）

### 固有名詞を入れる

「表計算ソフト」→「Googleスプレッドシート」
「あるツール」→「Stripe の支払いリンク」

### 失敗・迷い・限定を書く

AIは失敗を書きません。これが最大の差です。

- 「最初にやったのはまさにそれで、使い物になりませんでした」
- 「ここは最後まで悩みました」
- 「100問前後までは問題なく動きます。それ以上は別の話です」

**「うまくいかなかった話」が1つも無い記事は、人間が書いたようには読めません。**

### 自分にしか書けない一文を各セクションに1つ

その場の細部です。「承認画面で戸惑う人が多い」「大文字・小文字の違いで画像が出なかった」——AIが知りようのない具体です。

---

## 5. やってはいけない直し方

- **全部を口語にする** — 「〜っす」「〜なんですよね」を撒くと、今度は別の意味で読みにくくなります。基本は「です・ます」のまま、リズムだけ崩す
- **絵文字と「！」で誤魔化す** — AI臭は消えず、軽く見えるだけです
- **無理に長くする** — AI原稿の悪癖は水増しです。**直す作業の8割は削ること**になります

---

## 実際の手順

1. ChatGPT の原稿を `note/drafts/NNN-スラッグ.md` に貼る
2. `node note/tools/ai-check.js note/drafts/NNN-スラッグ.md` を実行
3. 【要修正】をすべて潰す（機械的に置換できる）
4. 【文体】の指摘を見て、短文を足す・段落を割る
5. **各セクションに「自分にしか書けない一文」を1つずつ入れる**（ここは手作業。ここが本番）
6. 「まとめ」を消すか書き換える
7. もう一度 `ai-check.js` を実行して確認
8. **音読する。** 言いにくい箇所は不自然な箇所です

最後の音読が一番あてになります。ツールは目安です。
