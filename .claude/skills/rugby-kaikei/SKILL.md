# rugby-kaikei: 会計の計算と書類生成

**このスキルの目的は、会計の数値をチャット上で手計算しないことにある。**
過去に名簿の重複1件で全費用の再計算が必要になり、コーチの日程変更のたびに
人数表を作り直すという事故が起きている。数値は必ず下記のシステムで算出する。

## 絶対の原則

1. **金額・人数をチャットの中で電卓的に計算して答えない。** 必ずコマンドを実行し、
   その出力を提示する。
2. **生成物（output/ 配下のxlsx・docx）を手で編集しない。** データを直してから
   再生成する。手で直すとデータと生成物が食い違い、次回の計算が壊れる。
3. **データファイルを直したら必ず `check` を通す。** 警告が出たら潰すか、
   潰せない理由を記録に残す。

## データの場所（唯一の入力）

```
data/rugby/roster-2026.csv          部員名簿。参加可否・合流日・合流食
data/rugby/camp-2026-summer.yml     日程・単価・大人の帯同・徴収額の内訳
data/rugby/expenses-2026-summer.csv 支出台帳。立替者・会計分類A/B/C
```

人が触ってよいのはこの3ファイルだけ。書類はすべてここから生成される。

## コマンド

```bash
python3 -m scripts.kaikei check      # 全検証。まずこれを実行する
python3 -m scripts.kaikei headcount  # 日別・食事別の人数
python3 -m scripts.kaikei balance    # 収支
python3 -m scripts.kaikei settle     # 立替金の精算表
python3 -m scripts.kaikei report     # xlsx一式を output/ に生成
python3 tests/test_kaikei.py         # 計算ロジックの回帰テスト
```

## 領収書を受け取ったときの手順

写真やレシートを渡されたら、読み取って `expenses-*.csv` に1行追加する。

- `category`: A=校友会予算 / B=父母会予算 / C=都度徴収。
  **対戦校への手土産・メディカル費・補食はB**（合宿費に混ぜない部のルール）。
- `payer`: 立て替えた人。部の現金から払ったなら `部`。
- `settled`: 返金済みなら `yes`、未精算なら `no`。
- `receipt`: 連番（r001…）。現物の領収書にも同じ番号を書いておくと照合できる。

追加したら `check` を実行し、`settle` で返金額を確認する。

## check が報告すること

| 検証 | 何を防ぐか |
|---|---|
| 曜日の検算 | 「7月1日(火)」のような曜日誤記（過去に配布事故あり） |
| 申告人数との突合 | 名簿とホテルへの申告人数のズレ |
| ホテル請求との突合 | 請求書の金額ミス、人数の分母違い |
| 収支の突合 | 徴収額と支出の辻褄 |
| 未精算の立替 | 先生への返金忘れ |
| **支出が1件も無い日の検出** | **領収書の回収漏れ**（昨年は雑費36件。7日間で支出ゼロの日は不自然） |
| 会計分類の混在 | 父母会予算(B)を合宿費に混ぜる誤り |

## 書類の様式

`docs/rugby/2026夏合宿_会計記録.md` の「昨年（2025年度）の様式と前例」に、
昨年の会計報告書のレイアウトと費目名を記録してある。**費目名は昨年の表記を
そのまま使う**（雑費／収支差額／合宿残金／予備費未使用返金分）。
保護者が見慣れた形式を崩さないため。

## 前例として確定していること

- 顧問の宿泊費・交通費・昼食代は**収入**に計上（生徒徴収とは別財源）
- コーチの宿泊・交通費・謝礼は**支出**の独立費目
- 予備費の未使用分は返金する
- 余った残金は「合宿残金」として合宿後のプロテイン代等に充当（返金しない）
- 対戦校への手土産は父母会予算(B)で別精算

## 新しい合宿を追加するとき

`camp-<id>.yml` と `expenses-<id>.csv` を同じ形式で作る。
名簿は年度単位なので `roster-<年度>.csv` を使い回す。
単価はホテルの請求書の実績値を入れること（見積値のままにしない）。
