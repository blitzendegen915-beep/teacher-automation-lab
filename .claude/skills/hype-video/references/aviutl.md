# AviUtl の導入と操作

## 必要なもの

この手順は **従来版の AviUtl（1.10）＋ 拡張編集（0.92）** が前提。

| ソフト | 用途 |
| --- | --- |
| AviUtl 本体（`aviutl.exe`） | 編集ソフト本体 |
| 拡張編集プラグイン（`exedit.auf`） | タイムライン編集。これがないと始まらない |
| L-SMASH Works（`lwinput.aui`） | スマホやカメラの MP4/HEVC を読むための入力プラグイン |
| x264guiEx | MP4 で書き出すための出力プラグイン |

導入手順はバージョンで変わるので、各配布ページの説明に従う。

> 新しい **AviUtl2（ExEdit2）** はフォルダ構成もスクリプトの文字コードも従来版と異なる。
> ここに書いた内容は従来版向け。ユーザーがどちらを使っているか分からないときは確認する。

## スクリプトの設置

1. `exedit.auf` が置いてあるフォルダを開く
2. その中に `script` フォルダを作る（あればそのまま使う）
3. `.anm` ファイルをコピーする
4. AviUtl を起動し直す
5. オブジェクト設定ダイアログ右上の「＋」→「アニメーション効果」に名前が出れば成功

**文字コードは Shift-JIS、改行は CRLF。** UTF-8 で保存するとトラックバーの項目名が
文字化けする。ユーザーがメモ帳で開いて保存し直すと壊れるので、その注意も併せて伝える。

新しくスクリプトを書いたら、UTF-8 で書いてから変換する。

```bash
iconv -f UTF-8 -t CP932 in.anm -o out.anm
python3 -c "
b=open('out.anm','rb').read().replace(b'\r\n',b'\n').replace(b'\n',b'\r\n')
open('out.anm','wb').write(b)"
```

Git に置くなら、改行を変換されないよう `.gitattributes` に `*.anm -text` を書く。

## .anm の書き方

```
--track0:名前,最小,最大,初期値,刻み
--check0:名前,初期値(0か1)
@効果名
（ここから下が Lua 5.1）
```

よく使う変数と関数。

| 名前 | 意味 |
| --- | --- |
| `obj.time` / `obj.totaltime` | オブジェクト先頭からの秒数 / 全体の秒数 |
| `obj.frame` / `obj.totalframe` | 同じくフレーム単位 |
| `obj.ox` `obj.oy` `obj.rz` | 位置のずらし量(px) / 傾き(度) |
| `obj.zoom` `obj.alpha` | 拡大率(1.0=100%) / 不透明度(1.0=不透明) |
| `obj.track0`〜`3` `obj.check0` | トラックバーとチェックボックスの値 |
| `obj.layer` `obj.index` | レイヤー番号 / 個別オブジェクトの通し番号 |
| `rand(最小,最大,シード,フレーム)` | 整数の乱数。シードとフレームを渡すと毎フレーム暴れない |

**必ず加算・乗算で書く。** `obj.ox = 値` と代入すると、他の効果や
ユーザーの座標設定を打ち消してしまう。`obj.ox = obj.ox + 値` が正しい。

### AviUtl なしで挙動を検証する

`obj` を模したテーブルを用意して Lua を走らせれば、実機なしで確認できる。

```bash
pip install lupa
```

```python
from lupa import LuaRuntime
L = LuaRuntime()
t = L.eval("function() return {} end")()
for k, v in dict(ox=0.0, oy=0.0, zoom=1.0, alpha=1.0,
                 time=0.0, totaltime=3.0, layer=1, index=0,
                 track0=0.0, track1=0.0, track2=0.0, track3=0.0,
                 check0=False).items():
    t[k] = v
L.globals().obj = t
L.globals().rand = L.eval("function(a,b,s,f) return a end")
L.compile(open("body.lua").read())()   # @行より下だけを渡す
print(t.oy, t.zoom, t.alpha)
```

時間を変えながら呼んで、期待どおりに動くかを確かめる。
構文エラーはこの時点で出るので、実機で「効果が出ない」と悩まずに済む。

## 色味を作る

**カットごとに色を調整すると必ずバラバラになる。**
一番上のレイヤーに色味用のフィルタを1本通しで置く。拡張編集では、
フィルタ効果のオブジェクトは**それより下のレイヤーすべて**に掛かる。

1. 一番上の空きレイヤーで右クリック →「メディアオブジェクトの追加」→「フィルタ効果の追加」
2. 動画全体の長さまで右端を伸ばす
3. 設定ダイアログ右上の「＋」から効果を積む

積む順番の目安。

| 順 | フィルタ効果 | 狙い | 目安 |
| --- | --- | --- | --- |
| 1 | 色調補正 | コントラスト・彩度・色相 | 解析した数値に合わせる |
| 2 | グロー | ハイライトを柔らかく光らせる | 強さ 20〜40 / しきい値 高め |
| 3 | シャープ | わずかに輪郭を出す | 10〜20 |
| 4 | ノイズ | フィルムのざらつき | 10以下 |
| 5 | 色ずれ | 端の色をずらす | 1〜3。かけすぎると一気に安っぽい |

**迷ったら弱くする。** 「シネマティックに見えない」ときの原因はたいてい掛けすぎ。

### 黒を持ち上げる（フィルム調）

解析で黒レベルが 15〜25/255 だった場合、黒が潰れていない。これを再現するには
色調補正だけでは足りないので、**黒い単色の図形を全面に置いて不透明度を92〜95%にする**か、
コントラストを下げて明るさをわずかに上げる。暗部だけが持ち上がり、フィルムらしくなる。

### 黒帯（レターボックス）

1. 一番上のレイヤーに「図形」を追加し、四角形・黒にする
2. 画面幅より大きくして、Y座標で上端へ寄せる
3. コピーして下端にも置く

必要な高さは解析スクリプトが計算して出す。1920×1080 の場合の目安は、
2.35:1 で上下 約130px ずつ、2.15:1 で 約95px ずつ。

**帯で顔や足元が切れないよう、撮影時から上下に余裕を持たせる。**

## 書き出し

1.「ファイル」→「プラグイン出力」→「拡張 x264 出力(GUI) Ex」
2. 保存先を決めて「ビデオ圧縮」で設定

| 項目 | 設定 |
| --- | --- |
| 映像 | 1920×1080 / 60fps |
| ビットレート | 12,000〜20,000 kbps |
| 音声 | AAC 192 kbps |

書き出しは実時間の数倍かかる。2分の動画で10〜30分みておく。
書き出したら **必ずスマホでも見る**。PC の大画面では文字の小ささや音量の不足に気づけない。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| スクリプトが一覧に出ない | `script` フォルダの場所が違う。`exedit.auf` と同じ階層か確認 |
| 項目名が「?????」になる | UTF-8 で保存されている。Shift-JIS に直す |
| 動画が読み込めない | L-SMASH Works が無い。HEVC のスマホ動画で特に起きる |
| プレビューが重い | プレビュー解像度を 1/2 に下げる。書き出し画質には影響しない |
| スローがカクカクする | 素材が60fps以下。120fpsで撮り直すしかない |
| 揺らすと画面端に黒が出る | そのオブジェクトの拡大率を先に105%にしておく |
| 音とカットがズレる | 1〜2フレーム単位で動かす。`beat_punch` なら `ズレms` で調整 |
| なんとなく安っぽい | 色ずれとノイズを半分にする |
| 途中で飽きる | 長すぎる。2分を超えていたら削る |
